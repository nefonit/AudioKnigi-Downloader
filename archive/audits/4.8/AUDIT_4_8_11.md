# Audit 4.8.11

## Проверено по загруженному архиву 4.8.10

### Подтверждённые и исправленные проблемы

1. `_refresh_book_timing_ui()` был безопасен только при текущих call-site, которые уже оборачивали его в `self.ui(...)`. Сам метод при прямом вызове из worker-потока мог обратиться к `Treeview`. В 4.8.11 метод сам определяет поток: в Tk-потоке применяет изменения сразу, в worker-потоке отправляет callback через `UIEventBus`.
2. `_on_window_focus_for_clipboard()` теперь дополнительно использует `getattr(self, "_clipboard_offer_after", None)`, хотя атрибут и ранее инициализировался в `AudioKnigiApp.__init__`.
3. `continue_unfinished()` больше не предполагает наличие всех Tk-переменных. Восстановление использует безопасное присваивание, допускает частично построенный UI и не падает с `AttributeError`/`TclError`.
4. При восстановлении нескольких книг `resume_selected_indices` явно очищается до добавления записей в очередь.
5. Переход на вкладку восстановления использует логический селектор (`book` / `queue`) с fallback на видимую подпись.

### Проверено, исправление не требовалось

- `_main_download_worker()` уже содержал `except Exception` и `finally: self.set_busy(False)` в загруженной 4.8.10. Добавлен регрессионный тест с искусственной дисковой ошибкой, подтверждающий сброс `busy`.
- `_clipboard_offer_after`, `_last_clipboard_offer`, `last_completed_folder` и `speed_history` уже инициализировались до привязки пользовательских событий.
- `ui_kit.py` не оборван: модуль и `AccessibleLabel._apply_theme_colors()` полностью компилируются.
- `tk_popup(...)/grab_release()` оставлен без изменения: это стандартный Tkinter-шаблон освобождения menu grab; воспроизводимого самопроизвольного закрытия меню в текущем коде не найдено.
- Кэш ключей обложек очереди/истории не создаёт текущего дефекта.
- TrayManager 4.8.10 уже содержит отложенный повторный show через `_show_when_retired`.
