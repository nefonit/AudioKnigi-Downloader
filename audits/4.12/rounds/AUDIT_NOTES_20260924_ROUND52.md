# Round 52 audit notes — 2026-09-24

Round 52 reviews the supplied post-Round-51 audit against the actual Round 51 source tree. Recommendations were not applied mechanically: confirmed runtime/privacy issues were fixed, while architectural/style observations and already-correct behavior were left unchanged.

## Confirmed fixes

- **Embedded Windows paths with spaces:** support-log sanitization now masks filenames such as `D:\Audiobooks\01. Введение.mp3` completely while preserving trailing text such as `not found`. Multi-dot names such as `book.part.mp3` are covered as well.
- **Support-bundle sanitizer efficiency/API:** drive/UNC regexes are compiled once at module scope rather than per `_privacy_path` call, and `_privacy_path` accepts both `str` and `pathlib.Path` values.
- **Settings legacy migration:** when `auto_chunk_min_kbytes_per_sec` exists but is `None`, a valid legacy `auto_chunk_min_kbps` value is now retained before the old key is removed.
- **Segment-count normalization:** zero, negative, non-numeric and values above the supported 1..8 range normalize to `auto`; valid 1..8 values remain explicit.
- **Qt entry-point exit contract:** `main() -> int` now maps `run_qt(...) is None` to exit code 0 and casts non-None codes to int.
- **Book-flow malformed indices:** internal processing skips malformed/boolean track indices instead of raising `TypeError`/`ValueError` while assembling the active selection.
- **Download-request boolean indices:** `bool` is explicitly rejected as a track index, so `True`/`False` cannot silently become tracks 1/0. `build_download_request` now uses the canonical `DownloadRequest.track_index` validator.

## Reviewed and intentionally unchanged

- `_clear_stale_source_downloads` remains tied to engine-owned `_source`/`_repair_source` names. The repair path is derived from `original_source_paths`, which itself comes from `_source_target_assignments`; the reported arbitrary custom-source filename scenario is not generated by this flow.
- Adaptive Range workers use a static job queue. A parked worker exiting after `jobs.empty()` cannot miss jobs that are later appended because this implementation does not append new jobs during the transfer. This is a tuning observation, not a correctness failure.
- `ProbeMixin._estimate_required_space` does rely on `_source_target_assignments` supplied by the composed downloader facade. Current production composition and dedicated tests satisfy that contract; moving the method to a new shared helper would be an architectural refactor.
- `SearchResult.author_inferred` exists in `models.py`, so the constructor call is valid.
- `_audioknigi_description_from_html` is imported and used by `BookAnalysisService`; despite the leading underscore it is not dead code.
- The `typing.Iterable` versus `collections.abc.Iterable` difference is style-only for the supported Python >=3.11 range.
- `..config.settings` is the correct package path in this tree.
- Queue `selected` versus resume-manifest `parts` is an intentional representation boundary; `_normalize_queue_download_mode` accepts the resume alias and maps it to the queue UI mode.
- The report's positive findings around cancellation cleanup, root-scan limits, safe filename rendering, DNS CNAME loop protection, Qt 6 `event.position()`, daemonized Windows sound shutdown, cover normalization and screen-reader row descriptions were retained unchanged.

## Windows 10 / Windows 11 source review

The source/build surface was re-scanned separately from the report. Windows-specific runtime calls are limited to broadly available APIs such as `user32.RegisterHotKey`/`UnregisterHotKey`, `winsound.MessageBeep`, `CREATE_NO_WINDOW`, `STARTUPINFO`/`SW_HIDE`, Qt system tray/multimedia and normal filesystem handling. No code path was found that requires a Windows-11-only native API. The release toolchain remains Windows x64-focused and the repository contains an explicit frozen-EXE Windows acceptance runner. This Linux environment cannot substitute for launching the final one-file EXE on real Windows 10/11, so frozen runtime, tray, multimedia, Edge/Playwright and NVDA/JAWS acceptance remain release-side checks.
