## 1 INTRODUCTION (Введение)

План задаёт порядок проверки системы AudioKnigi Downloader 4.12.42 Qt-only под Windows до публичного релиза. История тестирования ранних версий и Round 2–90 учитывается как источник регрессий, но не как свидетельство текущего E2E PASS.

## 2 SCOPE (Область тестирования)

Включено: 3 провайдера, поиск и варианты озвучки, анализ, главы/цельная MP3, HTTP Range/DNS, FFmpeg, очередь, история/резервные копии, плеер, настройки/миграции, локализация, Easy/Advanced, диагностические отчёты, установка Windows и доступность NVDA/JAWS.

Не включено: серверная инфраструктура сторонних сайтов, сертификация по WCAG, ОС macOS/Linux как целевые платформы; производительность сторонних сайтов без контролируемых стендов.

## 3 QUALITY OBJECTIVES (Цели качества)

Отсутствие открытых Blocker/Critical, исключение безвозвратной потери файлов/очереди; точная загрузка и resume; отсутствие секретов в логах; доступность всех главных действий через клавиатуру и NVDA/JAWS; воспроизводимый Windows билд; перевод системных состояний на RU/UK/DE/EN.

## 4 TEST APPROACH (Подход)

Использовать smoke → focused regression → full pytest → build audit → Windows E2E → NVDA/JAWS UAT. Положительные и отрицательные сценарии на контролируемом HTTP сервере и только разрешённых публичных источниках. Контроль SHA/артефактов каждого запуска; отдельная регистрация blocked/skip.

## 5 ROLES AND RESPONSIBILITIES (Роли)

Владелец продукта утверждает критерии и релиз; QA готовит и ведёт артефакты; разработчик исправляет дефекты и добавляет автотесты; исполнитель Windows UAT проверяет экранные дикторы. Указанные роли функциональны; реальные лица/подписи без подтверждения не назначаются.

## 6 ENTRY AND EXIT CRITERIA (Критерии входа/выхода)

Entry: зафиксированы commit SHA, EXE, тестовое окружение, контрольные данные, доступность источников, базовая стратегия и тест-кейсы.

Exit / Go: 0 открытых Blocker/Critical; успешные обязательные P1, все действующие CI checks на идентичном SHA; все установки, загрузка/восстановление и NVDA/JAWS UAT подтверждены; отсутствие невоспроизводимых/необоснованно пропущенных P1; письменное approval. **На дату составления Exit не выполнен: Windows UAT/EXE evidence отсутствует.**

## 7 SUSPENSION AND RESUMPTION (Приостановка/возобновление)

Приостановка: потеря данных, нарушение приватности, неработающий основной сценарий, недоступный тестовый сервер или сборка; возобновление после фикса, нового SHA и confirmation test плюс регрессия.

## 8 TEST STRATEGY (Стратегия)

Подробности: `TEST_STRATEGY.md`. Severity: Blocker, Critical, Major, Minor; Priority P1–P3. Тестирование модульное, интеграционное, системное, smoke, регрессионное, exploratory, accessibility и privacy/security. Валидация проводится на основных пользовательских сценариях.

## 9 RESOURCES AND ENVIRONMENTS (Ресурсы и окружения)

Windows 64-bit (официальная система), Python 3.11 и CI 3.14.7, PySide6, FFmpeg/FFprobe, Microsoft Edge, NVDA и JAWS, реальные тестовые MP3, HTTP stub с Range/404/503/разрывом, свободное место для больших файлов. Полные сведения: `TEST_DATA_ENVIRONMENTS.md`.

## 10 TEST SCHEDULE (План-график)

Этап 1: инвентаризация исторических свидетельств (документально завершена); этап 2: актуализация кейсов/RTM и прогон pytest (исторические результаты собраны, новый официальный прогон ожидает); этап 3: Windows EXE+NVDA/JAWS+network UAT; этап 4: дефекты/ретест; этап 5: решение Go/No-Go. Сроки не назначены, поскольку они не подтверждены владельцем.
