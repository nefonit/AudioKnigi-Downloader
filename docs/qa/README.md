## Состав комплекта

1. `TEST_STRATEGY.md` — общая стратегия и правила QA.
2. `TEST_PLAN_4.12.42.md` — тест-план версии по структуре 11 разделов учебного образца.
3. `REQUIREMENTS.md` — 14 групп требований. `ATOMIC_REQUIREMENTS.md` / `atomic_requirements.csv` — 79 атомарных проверяемых критериев, составленных для кейсов (требуют согласования).
4. `TEST_CASES.md` / `test_cases.csv` — 79 тест-кейсов с шагами и ожидаемым результатом; статус Not Run.
5. `CHECKLISTS.md` / `checklists.csv` — 94 проверок по подсистемам.
6. `TRACEABILITY_MATRIX.md` / `traceability.csv` — связи крупных групп; `ATOMIC_TRACEABILITY.md` / `atomic_traceability.csv` — связь FR → TC → CL; pytest node-id требует дополнительной разметки.
7. `DEFECT_REGISTER.md` / `defects_historical.csv` — исторические дефекты с прямыми ссылками на первоисточник; реестр не равнозначен открытому баг-трекеру.
8. `TEST_EXECUTION_HISTORY.md` — история подтверждённых результатов по датам/раундам и ограничениям.
9. `HISTORY_EVIDENCE.csv` — навигационный реестр всех 88 доступных Round 2–90 аудитов.
10. `HISTORICAL_FINDINGS.csv` — вся автоматически извлечённая история подтверждённых исправлений с исходными строками; `TEST_SUITES.md`, `RISK_REGISTER.md` — покрытия и продуктовые риски.
11. `RELEASE_READINESS.md` — критерии решения Go/No-Go и незакрытые доказательства.
12. `TEST_DATA_ENVIRONMENTS.md` — среды и тестовые данные, включая Windows/NVDA/JAWS.
13. `QA_TEMPLATES.md` — формы новых тест-кейсов, дефектов, запусков, ревью и изменений.

## Правила обновления

- Каждый новый баг: создать запись с ID, шагами, Actual/Expected, ссылкой на коммит и подтверждающий тест.
- Каждое изменение требования: обновить Requirements → RTM → Cases → Checklist и соответствующие автотесты.
- Каждый тестовый прогон: фиксировать SHA, дату, платформу, команду, PASS/FAIL/SKIP и логи.
- Ни один старый тест не считается пройденным на новом EXE автоматически.
- Не считать исторически сохранённые тесты из `archive/tests/` частью активного зелёного прогона.

## Стандарты/образцы

Структура тест-плана отражает приложенный пользователем учебный Test Plan (разделы Introduction—Approvals). Табличные колонки Test Case, Checklist и Bug Report соответствуют приложенным учебным XLSX; термины Test Basis, Testware, RTM, risk-based testing, confirmation/regression и дефекты согласованы с ISTQB CTFL v4.0.1. Эти образцы не описывают функциональность AudioKnigi — функциональность проверена по коду проекта.

## Известные ограничения

Не проведено подтверждённое ручное Windows+NVDA/JAWS тестирование на указанном SHA; нет сертификата релизной приёмки EXE; часть сетевых тестов в разных ревизиях сознательно исключалась или зависала. Поэтому статус текущей версии — **не утверждён для production**.
