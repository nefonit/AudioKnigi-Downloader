# Test Strategy — AudioKnigi Downloader

AudioKnigi Downloader 4.12.42 | QA Baseline v1.0 | 2026-10-15

## 1. Назначение и принципы

Обеспечить контролируемую проверку Windows PySide6-приложения для поиска, скачивания и прослушивания аудиокниг. Применяется риск-ориентированное тестирование: пользовательская потеря данных, повреждение медиа, утечка секретов, зависание и недоступность скринридеров оцениваются прежде оформления/косметики. Основа — код, требования-производные, история релизов и bug reports; тестирование не доказывает отсутствие дефектов.

## 2. Test levels

- Static: compileall, type/interface/source audits, локализация, паритет и анализ исключений.
- Unit: `tests/unit/` для настроек, данных, локализации и компонентов загрузчика.
- Integration: `tests/integration/` для провайдеров, сети, аудио, очереди, плеера, UI-контрактов, приватности.
- System/E2E: Windows EXE, три источника, реальные файлы, отказные сценарии, FFmpeg/FFprobe, Edge/Playwright.
- Acceptance: NVDA/JAWS + клавиатура + четырёхъязычная проверка + письменное решение владельца.

## 3. Techniques

Equivalence partitioning: URL валиден/невалиден, индексы глав целые/дробные/отрицательные; boundary-value: длины, таймкоды, диск, размер обложек; decision tables: повторы/404/Range/удаление исходника; state-transition: очередь Pending/Running/Interrupted/Paused/Completed, плеер Play/Pause/End; exploratory: сбои сетей, внешний скринридер. Для каждого регрессирующего бага сохранять автоматизированный тест.

## 4. Test types and priorities

Функциональное, smoke, регрессия, совместимость Win/Python/Qt, устойчивость, безопасность и приватность, UX, accessibility, локализация, performance smoke. P1: невозможность скачивания, потеря пользовательских данных, утечка приватных данных, падение, нарушение основного интерфейса NVDA/JAWS. P2: деградация отдельной функции. P3: локальные текстовые/визуальные дефекты без влияния на доступность.

## 5. Automation and manual balance

Автозапуск CI выполняется на Windows Python 3.11 и 3.14.7 (проверить фактический запуск и логи конкретного SHA). В Linux возможна локальная быстрая проверка без PySide6, но она не заменяет системный тест Windows. Ручные кейсы **Not Run** до независимого выполнения.

## 6. Defect life cycle

New → Confirmed → In Progress → Fixed → Ready for QA → Verified → Closed; альтернативы Reopened, Rejected (с аргументом), Deferred (с риском и одобрением). Обязательные поля: ID, SHA и версия, окружение, Steps, Actual, Expected, severity, priority, evidence, fix commit, retest.

## 7. Risk matrix

| Риск | Влияние | Приоритет проверки |
|---|---|---|
| Неполная или повреждённая загрузка | Высокое | P1 |
| Потеря очереди/history/resume | Высокое | P1 |
| Секреты в support bundle | Высокое | P1 |
| Недоступность NVDA/JAWS | Высокое | P1 |
| Падение/зависание из-за сети, DNS, FFmpeg | Высокое | P1 |
| Некорректные переводы динамического текста | Среднее | P2 |
| Косметика темы | Низкое, если контраст/доступность не затронуты | P3 |

## 8. Test completion and metrics

Собирать collected, passed, failed, skipped, blocked, duration, environment, version, SHA, Windows manual acceptance (отдельно NVDA и JAWS), покрытия функций, открытые P1/P2. Не смешивать статистику разных ревизий. Любое требование без прямого проверочного доказательства = gap.

## 9. Governance

Изменение кода/функции → обновить тест-кейс, RTM, checklist, регрессионные тесты и changelog в одном PR/коммите. Релизный Go/No-Go утверждает владелец продукта после ознакомления с рисками.
