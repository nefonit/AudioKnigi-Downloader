# Автоматический DNS + резервное TCP-подключение (31.10.2026)

**База:** AudioKnigi Downloader 4.12.42, эксперимент с 8 источниками и HTTP/SOCKS5-прокси. Релизный номер не изменён, Windows EXE не собран.

## Что изменено

- В режиме DNS `auto` адреса Cloudflare DoH используются в первую очередь. Если соединение TCP с этими IP-адресами не удалось, программа проверяет системный DNS и **только новые** адреса, если они отличаются. Число попыток и время ожидания ограничены, одинаковый IP повторно не запрашивается.
- Для Python-HTTP-запросов в `auto` применяется тот же внутренний локальный прокси, что для Playwright и FFmpeg, чтобы выбор маршрута действовал на поиск и загрузку согласованно.
- HTTP-повторы при ошибках внутреннего прокси в `auto` сокращены: локальный мост уже пробует резервные маршруты, дополнительные многократные ретраи бесполезно задерживали поиск.
- Строгий `cloudflare` **не** обращается к системному DNS для публичных имён. Режим `system` и явный пользовательский HTTP/SOCKS5-прокси сохраняют приоритет и прежние правила. Локальные и служебные имена обслуживает Windows.
- Ручная кнопка проверки источников теперь делает DNS/TCP/TLS/HTTPS HEAD-проверку и выводит IP адрес, источник DNS/маршрут, время DNS, TCP и TLS, HTTP-код или категорию сетевой ошибки с безопасным кодом Windows, когда он доступен.
- Фоновая проверка при запуске оставлена облегчённой; новые результаты выводятся обычным читаемым текстом и доступны экранным дикторам по прежнему диалогу.

## Как проверить на Windows

1. Не заменяйте стабильную установленную программу, сохраните резервную копию. Распакуйте **исходники** в отдельную папку. Для запуска используйте старые инструкции `README.md` и `run_qt.bat` с установленными зависимостями; для собственного EXE нужен Windows-процесс сборки.
2. Выключите Cloudflare One. В программе перейдите в «Настройки → Загрузка и сеть», выберите DNS «Автоматически», оставьте пользовательский прокси пустым, сохраните.
3. Нажмите «Проверить подключение ко всем источникам». Сравните записи для `knigavuhe.org`, `akniga.org`, `yakniga.org`, `uknig.com` с результатами в режиме «Только Cloudflare».
4. Для сайтов, дающих ошибку, смотрите `DNS/маршрут`, `IP`, `DNS/TCP/TLS мс` и категорию ошибки. Не отправляйте приватные ссылки на книги, cookies или пароли.

## Ограничения

- **DNS не заменяет WARP/VPN.** Если сервер недоступен по TCP для обоих маршрутов/IP, результат останется тайм-аутом. При HTTPS-фильтрации/блокировке TLS смена DNS также не поможет.
- DNS-система Windows иногда возвращает тот же IP, что Cloudflare. В таком случае повторного подключения на тот же IP не будет. Проверка IP не обещает доступность сайта.
- Ручная проверка использует HTTP `HEAD`, а поиск может использовать `GET`, JavaScript или API, поэтому успешно ответивший сайт всё равно может быть недоступен для конкретного действия. Проверка не скачивает книгу.
- Точное подключение в Windows и работа с NVDA/JAWS требуют испытания на компьютере пользователя. Эти изменения не обойдут блокировки и не гарантируют доступность akniga.org/yakniga.org/uknig.com без WARP.
