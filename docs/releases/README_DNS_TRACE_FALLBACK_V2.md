# AudioKnigi Downloader 4.12.42: расширенная проверка DNS / TCP (эксперимент)

## Зачем обновление

В диагностике пользователя без Cloudflare One доступно 4 из 8 источников и при выборе `auto`, и при выборе `cloudflare`. Четыре недоступных источника возвращали TCP-тайм-аут около трёх секунд. Это не доказывает сбой DNS: серверы могли быть недоступны на уровне сети, а диагностика показывала только один IP и не указывала, запускался ли резервный вариант.

## Изменения

- Ручная диагностика теперь получает до **8 секунд** на попытки TCP-подключения вместо 3 секунд; фоновая проверка при старте остаётся короткой (3 секунды).
- Автоматический DNS резервирует часть **общего** времени соединения для альтернативного **отличающегося** IP системного DNS. Это исправляет ситуацию, когда первая попытка израсходовала весь бюджет и резервного подключения не было. Сокращение бюджета первого IP может изменить время ожидания медленных серверов; при необходимости используйте строгий режим DNS.
- Сохраняется список IP, полученных от Cloudflare и системного DNS, а также статус каждого фактически выполненного TCP-подключения. Один и тот же IP не запрашивается повторно только ради другого названия DNS-провайдера.
- При выборе `cloudflare` системный DNS может **опрашиваться только для сравнения в ручной диагностике**. Для TCP-подключения этот режим по-прежнему использует исключительно Cloudflare IP. Простой поиск и скачивание не выполняют сравнения.
- В отчёте отдельно обозначены: одинаковые ответы DNS, отказ системного DNS, реальная попытка на другом IP, и исчерпание тайм-аута.
- Отчёт остаётся текстовым, читается экранными дикторами; добавлены RU/UK/DE/EN подписи. Отчёт не показывает секретные URL, токены или cookies.
- Запрос `HEAD /` проверяет только HTTPS главной страницы сайта. Это **не** проверка поискового API, выдачи книг и их скачивания.

## Как проверить на Windows

1. Распакуйте исходный ZIP отдельно от стабильной программы и запустите согласно `README.md` (для работы требуется установленное окружение Python/Qt). Это НЕ готовый EXE.
2. Выключите Cloudflare One; сначала выберите `auto`, затем `cloudflare` и нажмите «Проверить подключение ко всем источникам».
3. Сравните для `akniga.org`, `yakniga.org`, `uknig.com` и `knigavuhe.org` строки **Cloudflare DNS IP**, **Системный DNS IP**, **TCP-попытка** и **статус резервного подключения**.
4. Если оба DNS возвращают одинаковый недоступный IP, смена DNS без VPN/WARP/рабочего прокси не улучшит маршрут.
