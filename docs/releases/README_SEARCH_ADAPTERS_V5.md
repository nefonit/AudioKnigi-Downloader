# V5: поиск Akniga/Izib и ускорение резервного TCP-подключения

Экспериментальное дополнение к AudioKnigi Downloader 4.12.42 V4; версия основного приложения не меняется.

## Изменения

- `akniga.org`: реализован реальный поиск книг по каталогу `/search/books/pageN/?q=` (до 3 страниц, максимум 30 карточек). Из результатов исключаются превью, невалидные/внешние URL. Получение аудиофайлов и код HLS не изменены.
- `izib.uk`: парсер выбирает название из текстовой ссылки на книгу, а не из обложки; различает пустую выдачу и страницу неожиданного формата, поддерживает несколько страниц (до 30 результатов).
- Проверка источников: неподдерживаемый поиск, 0 найденных книг и сетевая/HTML-ошибка показываются раздельно. Поиск больше не должен выдавать фиктивное «0 результатов; 0 мс» для Akniga.
- Автоматический DNS: после успешного резервного TCP-подключения к *другому* IP системы ненадолго (90 секунд) запоминает этот адрес в оперативной памяти. При последующем соединении в автоматическом режиме сначала пробует его, с максимум 1,5 сек ожидания. Системный DNS в режиме «Только Cloudflare» для подключения не используется. В ручной диагностике всегда проверяется свежий маршрут без этой оптимизации.
- Переводы новых статусов: RU (исходные фразы), UK, DE, EN.

## Локальная проверка

- `python -m pytest -q tests/unit`: 107 тестов успешно.
- `python -m pytest -q tests/integration/test_search.py tests/integration/test_providers.py tests/integration/test_network.py`: 239 тестов успешно.
- `python -m pytest -q tests/integration/test_localization.py tests/integration/test_privacy_diagnostics.py`: 137 тестов успешно.
- В историческом аудите исключений (`tests/integration/test_quality_gates.py::test_exception_allowlist_has_no_stale_entries_and_is_sorted`) ошибка `akniga.py:_find_hls` выявлена **также в неизменённой V4**.

Тесты HTML используются как локальные образцы структуры, основанные на открытом коде AudioBookPlayer. Не удалось подключиться к реальным akniga.org и izib.uk в среде сборки; настоящий поиск, GUI Windows/NVDA/JAWS и HLS-загрузка остаются непроверенными. Возможны изменения разметки на сайтах.

## Проверка на Windows

1. Создайте резервную копию V4 перед установкой V5.
2. Для проверки реализации поиска включите Cloudflare One (чтобы исключить прежние сетевые тайм-ауты).
3. Введите в обычный поиск «Горбун» или «Шерлок Холмс» и включите Akniga и Izib. Проверьте названия, ссылки и отсутствие дублей.
4. В меню сетевой диагностики используйте «Проверить поиск по каждому сайту». Для LibriVox лучше проверять «Sherlock Holmes» — русское «Поттер» может естественным образом вернуть 0.
5. Затем выключите Cloudflare One и проверьте `knigavuhe.org` в автоматическом режиме DNS несколько раз за одну сессию. Скорость второй попытки может улучшиться; режим «Только Cloudflare» не использует кэшированные системные IP.
6. Если поиск выдаёт «изменилась структура сайта», сохраните журнал приложения без секретов и отправьте для обновления селекторов.
