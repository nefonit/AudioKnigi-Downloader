# Экспериментальная интеграция akniga.org (30 октября 2026)

**Исходник:** AudioKnigi Downloader 4.12.42 / Round 90.
**Статус:** экспериментальный исходный код, НЕ проверенный на реальном Akniga и НЕ Windows-релиз.
Изначальный ZIP пользователя не изменялся.

## Уже реализовано

- Ссылка книги вида `https://akniga.org/glubina-pogruzhenie-76-e` распознаётся в простом и расширенном режиме, а также в очереди.
- Новый provider `AKnigaProvider` зарегистрирован в `providers/registry.py`. Поиск по сайту пока не реализован; доступен анализ по прямой ссылке.
- `audioknigi/akniga.py`: открывает браузер Playwright, получает главы (включая `time_from_start` / `time_finish`) через AJAX сайта и перехватывает URI `.m3u8` при обычном воспроизведении.
- `audioknigi/download/network.py`: FFmpeg преобразует доступный HLS в временный MP3, который затем проходит существующую обработку и нарезку глав. Временная ссылка не сохраняется как константа.
- Не добавлены сторонние JS-крипты расшифровки, скрытые ключи, обход платного доступа или DRM.

## Проверено локально

- `python -m pytest -q tests/unit` — 31 успешный тест.
- Генерация тестового HLS при помощи FFmpeg и преобразование его в MP3: успешны и локальный файл, и HTTP через локальный сервер.
- Синтаксис исходных модулей: compileall успешно.

**Не проверено:** открытие страницы Akniga в реальном браузере, фактическая доступность AJAX, запуск плеера, получение `.m3u8` и полный аудиокнижный файл. Эта среда не имеет доступа к akniga.org. При изменении структуры сайта адаптер может не сработать. Полное тестирование Qt/NVDA/JAWS/Windows EXE не проводилось.

## Что нужно проверить на компьютере

1. Используйте только контент, на сохранение которого у вас есть права и разрешение.
2. Откройте проект в исходном виде и установите стандартные зависимости (см. корневой README). Playwright и Chromium должны быть доступны.
3. Запустите программу, вставьте ссылку на Akniga и нажмите «Анализировать».
4. Убедитесь, что видна таблица всех глав. Затем испытайте небольшую часть и проверьте соответствие начального и конечного времени.
5. При ошибке сохраните диагностический журнал и верните его для анализа. Нельзя считать провал подтверждением того, что сайт не поддерживается; возможно, требуется адаптировать метод поиска плеера.

## Ограничения и риски

- На сайте встречаются HLS-плейлисты с ограниченным сроком действия. В текущей архитектуре обновление ссылки инициируется прежде всего для HTTP 404/410, но некоторые серверы могут возвращать 403. Тогда может потребоваться повторный анализ книги.
- HLS нужно загружать целиком для выбранных глав общего потока (в приведённом примере примерно 9 часов), поскольку главы представлены временными отрезками одного потока.
- HLS транскодируется в 160 кбит/с перед дальнейшей обработкой; MP3 нельзя безопасно получать простой побайтной копией текстового `.m3u8`.
- Для потоков HLS ещё не реализованы полноценная пауза/докачка, прежний лимит скорости, точный процент скачивания и завершённые проверки соответствия временных границ.
- Сайт официально не предлагает экспорт файлов для прослушивания вне сервиса. Адаптер не предназначен для обхода ограничений доступа, DRM или скачивания книг без соответствующих прав.

## Что важно перед релизом

Рекомендуется отдельно проверить: обработку ошибок 401/403/404, истечение `expires`, сохранение/восстановление очереди, режим одного MP3, выбор одного отрывка, корректность метаданных, отмену через NVDA/JAWS, тесты на Windows. Пока это прототип, не заменяйте им стабильную сборку.

## Оптимизация HLS (31 октября 2026, эксперимент)

- При загрузке/восстановлении **не более 4 недостающих глав**, если их общая продолжительность составляет **не более 40% книги**, выбран исходный профиль без нормализации, используется прямое чтение временных интервалов HLS. При успешной проверке весь `_source.mp3` не загружается. Это работает только если HLS допускает позиционирование (`-ss`) и границы глав действительно совпадают с исходным потоком. Если нет — пробуем исходную полную загрузку; недостоверные частичные MP3 удаляются.
- Для полной книги, если исходный аудиокодек HLS уже MP3 и выбран режим «оригинал без нормализации», применяется FFmpeg `-c:a copy`, без перекодирования. При неподходящем для MP3-контейнера аудиокодеке выполняется один проход MP3-кодирования. Специальные пресеты 64k mono / 96k mono / 128k stereo учитываются при HLS-перекодировании.
- В ходе обработки FFmpeg отображает прогресс **медиавремени**, а также относительную скорость обработки в `x` (если она известна). Это не измерение фактической скорости Интернета и не обещание возобновления HLS с прежнего сетевого пакета. В режиме нескольких выбранных глав шкала прогресса теперь сквозная, без сброса на каждой главе.
- Уникальные временные файлы создаются через `mkstemp`; старые `.part` не изменяются, после отмены собственные временные файлы удаляются. Готовые главы используются в текущих проверках, ID3, метаданных и истории.

**Тесты:** 38 тестов `tests/unit` пройдены. Локальный тест FFmpeg с AAC-HLS подтвердил корректную нарезку временного отрезка и fallback при невозможности stream-copy. Полный `pytest tests --maxfail=1` остановился на существующей архитектурной проверке `test_active_tests_are_organized_by_behavior_not_phase_number`: в наборе уже есть тест с `audit`/`phase` в имени. Эта ошибка не связана с Akniga. Живая проверка сайта, Windows, JAWS/NVDA и точности всех границ книги не проводилась.

**Ограничения:** при загрузке всех глав требуется получить весь исходный поток, поэтому полная загрузка по-прежнему зависит от сервера и сети. Загрузка с HLS не поддерживает HTTP Range-докачку из середины, как обычный MP3. Для поиска книг на Akniga адаптер пока не применяется — только прямые ссылки на страницы книг. Используйте лишь контент, на сохранение которого есть разрешение.

## Сопоставление с AudioBookPlayer-master (экспериментальный HLS-параллелизм)

Источник идеи: предоставленный пользователем `AudioBookPlayer-master.zip` (Alex Filiov / AudioBookPlayer, лицензия MIT). В чужом проекте `ABPlayer/drivers/akniga.py` получает метаданные и поток, а `ABPlayer/drivers/downloaders/merged_m3u8_downloader.py` скачивает независимые HLS-сегменты параллельно, собирает их и нарезает по главам. В `ABPlayer/drivers/base.py` указан лимит **20** задач. Наш код написан независимо по той же архитектурной идее; исходники и сторонние JS-скрипты из чужого архива в дистрибутив не копировались.

### Новое в экспериментальной сборке

- Для *полной* HLS-книги при наличии подходящего VOD-плейлиста программа теперь сначала пробует получить сегменты параллельно (по умолчанию 6 задач, численное ограничение из настроек числа сегментов также соблюдается). После получения формируется локальный HLS-манифест, а FFmpeg объединяет/конвертирует поток из временных файлов.
- Для обычного MPEG-TS HLS и AES-128 HLS проверено корректное получение сегментов с сохранением их порядка, границ и `EXT-X-MEDIA-SEQUENCE`; стандартное декодирование HLS делает FFmpeg. Временные ключи AES-128 находятся только во временном каталоге и удаляются после завершения обработки.
- Индикатор во время параллельного этапа показывает количество завершённых сегментов, фактический объём и среднюю сетевую скорость; обработка FFmpeg занимает последние 30% шкалы. До завершения неизвестен абсолютный прогресс по длительности, если медиавремя недоступно.
- Применяется настроенный общий лимит скорости, если он задан. Для частичной загрузки глав сохраняется ранее реализованная адресная обработка FFmpeg.
- Если плейлист содержит мастер-манифест, байтовые диапазоны, fMP4 `EXT-X-MAP`, нестандартные/неполные HLS-расширения или сервер блокирует сегменты, программа возвращается к FFmpeg. При ошибке локальной сборки также предусмотрен однократный переход на обычный FFmpeg.
- Скачивание сегментов ограничено количеством параллельных задач и числом повторных попыток. Ошибочные временные файлы удаляются. Дополнительная проверка URL ограничивает допустимые сетевые ресурсы.
